# MimiBox 项目需求文档 V1.0

- **项目名称**：MimiBox（GPT 酱的四次元表情口袋）
- **GitHub 仓库**：`gpt-mimibox`
- **项目类型**：智能表情包仓库、Web 管理系统、AI 检索接口
- **执行方**：ChatGPT Work

## 1. 项目目标

建立 GPT 酱专用的、长期可维护的综合表情包库，涵盖猫狗、熊猫头、抽象梗、二次元、游戏、学习、情绪表达及日常互动。提供导入、去重、分类、搜索、随机获取、网页浏览和后续 AI Agent 集成能力。**必须区分真实可用的聊天集成与模拟演示**。

原则：实用优先、低成本、模块化、可持续扩充、版权合规、安全可控。

## 2. 核心功能

### 2.1 资源库（P0）

- 支持 PNG、JPG、GIF、WebP；在支持条件下兼容 APNG；动态图片保留动画。
- 支持批量导入、唯一 ID、来源追踪、分类标签、图片预览、增量更新、损坏检测。
- 初期目标 500～1000 张**授权允许使用**的真实图片；不足时如实说明，不能凑数。
- 记录格式、尺寸、大小、SHA-256、来源、许可、导入日期；避免大型动图导致仓库膨胀。

### 2.2 分类和标签（P0）

初始分类：猫猫狗狗、抽象搞怪、二次元、情绪表达、阴阳怪气、游戏梗、学习专用、日常互动、网络热梗、其他。每张图允许多个情绪、风格、场景标签；分类可配置和编辑。

### 2.3 AstrBot 资源包导入（P0）

重点调查：

- https://github.com/anka-afk/astrbot_plugin_meme_manager
- https://github.com/anka-afk/astrbot-meme-pack-index

Work 必须实际阅读仓库结构、文档、协议及许可证，核实资源包是否可再分发。设计适配器导入图片与元数据，保留原始来源、版本及许可，支持去重、增量更新、禁用/删除资源包。未知授权先进入待审核状态，不得直接公开发布。不要未经许可证检查复制插件代码。

### 2.4 检索与随机（P0）

- 支持关键词、分类、情绪、标签、使用场景筛选。
- 自然语言检索，如“震惊猫猫”“吐槽离谱发言”“鼓励我做数学题”。首版可用图片描述+标签的全文检索，向量检索作为后续增强。
- 搜索返回相关候选图、描述、标签、图片 URL、来源及授权信息。
- 支持全库随机、分类随机、情绪随机、排除近期重复。

### 2.5 自动分类与近似去重（P1）

- 可选视觉模型辅助生成描述、标题、标签和情绪，必须支持人工纠正。
- SHA-256 精确去重；可选感知哈希检测相似图，动态表情包须采用合理策略。
- 重复图片可合并来源记录，不可误删不同版本。

### 2.6 Web 页面（P0）

- 首页：总数、分类数、资源包数、搜索、随机表情包。
- 图库：响应式网格/瀑布流、懒加载、动图预览、筛选、排序、分页或虚拟列表。
- 详情：原图、标题、描述、标签、格式、大小、来源、许可证、复制图片链接。
- 管理：导入、上传、编辑、删除、查重、更新日志。
- 注意静态站点无法直接安全写入 GitHub：可使用本地脚本+Git、GitHub Actions/PR 审核，或带鉴权的后端；不做虚假可用按钮。

### 2.7 设计规范（P0）

- 可爱、活泼、轻盈，少量猫咪元素，但内容不局限猫咪。
- 避免模板化蓝白 AI 风格；浅色/深色模式，PC/平板/手机响应式。
- 图片为视觉中心，动效克制，移动端性能良好；支持键盘操作和基本无障碍访问。
- 可增加 MimiBox 吉祥物，但不能遮挡核心功能。

## 3. ChatGPT / Agent 集成

### 3.1 必须调查并实测（P0）

验证普通 ChatGPT 对话能否访问 MimiBox、能否直接展示原图、能否按上下文调用检索、新对话能否自动发现仓库，以及是否存在可用的正式 App/Connector 接入路径。分别记录“实测成功 / 理论可行未验证 / 需要手动操作 / 当前不支持”。**不能把模拟聊天、README 提示词或普通图片链接宣称为自动斗图功能。**

### 3.2 统一检索接口（P0）

设计逻辑接口：

- `search_memes(query, limit, filters)`
- `random_meme(category, mood)`
- `get_meme(id)`
- `list_categories()`

返回 ID、标题、描述、分类、标签、图片 URL、来源、许可证和相关性分数（适用时）。静态站点可先用 JSON 索引，不必为形式上的 API 部署服务器。严禁前端暴露密钥。

### 3.3 聊天使用策略（P1）

若集成能力允许：根据上下文匹配情绪，适度使用；严肃话题默认不发搞怪图；避免重复；遵守用户“不发表情包”的要求；不影响正常回答。

## 4. 推荐技术架构

- 前端：React + TypeScript + Vite + Tailwind CSS。
- 数据：JSON 元数据、静态图片、可离线生成的搜索索引。
- 工具：Python 导入/去重/校验脚本，GitHub Actions 自动化。
- 部署：GitHub Pages 或 Cloudflare Pages；优先免费低成本。
- 大型媒体存储须评估 Git 仓库体积、LFS、对象存储与 CDN 限制。

建议目录：

```text
gpt-mimibox/
├── README.md
├── LICENSE
├── docs/                 # 架构、集成、部署、版权策略
```

## 5. 版权与安全

- 能下载不等于能转载；每个资源包记录作者、仓库、许可证、限制、导入日期、版本。
- 仅将授权允许公开分发的图片部署到公共网站；不明确的资源先待审核。
- Token、API Key 不得进入前端或 Git 历史；管理写入需要鉴权。
- 上传文件必须校验大小、格式、内容及路径；不得执行不可信资源包脚本。
- 默认 GitHub 仓库 Private；未经用户确认，不得公开仓库或部署含未授权素材的图库。

## 6. 开发阶段及验收

### 阶段一：资源库（P0）

创建或检查 `gpt-mimibox` 仓库，调查 AstrBot 资源包，筛选许可，导入首批资源，建立分类/元数据，去重并生成索引。验收：真实图片可访问、唯一 ID、无损坏、数量真实、来源和授权可追踪。

### 阶段二：Web 站点（P0）

完成首页、图库、详情、搜索、筛选、随机和实际可用的管理路径，测试移动端并部署。验收：图片/动图可加载、功能可用、刷新路由正常、移动端不溢出、部署地址可访问。

### 阶段三：智能增强（P1）

自动描述、自动标签、语义检索、相似图检测、资源包增量更新。验收：自然语言能找到相关图片，结果可解释，错误标签可修正。

### 阶段四：ChatGPT 集成验证（P0 研究任务）

实际测试可用接入方式，记录成功、失败、限制及替代路径；至少提供一种真实可用的检索/展示方式，不得将自动发送能力虚报为完成。

## 7. 测试清单

- 功能：导入、搜索、筛选、随机、详情、更新、去重、编辑。
- 数据：Schema 校验、重复 ID、坏文件、缺失图片路径、许可证字段。
- 兼容：Chrome、Edge、Android 浏览器、多屏幕尺寸。
- 性能：大图库加载、搜索响应、动图内存、移动端滚动。
- 安全：密钥泄漏检查、上传校验、权限与公开资源审计。

## 8. Work 执行指令

请**直接执行开发、测试和部署**，而不是只输出方案：

1. 检查 GitHub 连接及现有 `gpt-mimibox` 仓库；不存在则创建 Private 仓库，存在则先审查，禁止覆盖已有成果。
2. 阅读 AstrBot Meme Manager 与资源索引，核实资源包结构和许可证。
3. 完成第一阶段并提交代码；再推进 Web 站点和测试。
4. 采用 `main` 稳定分支，可在功能分支开发，保留清晰提交历史。
5. 每完成一个阶段提交进度、更新 README/待办/已知问题，确保中断后可继续。
6. 公开发布任何图片或仓库之前，先检查授权并获得用户确认。
7. 继续进行智能检索和 ChatGPT 集成可行性验证，不得夸大功能。

## 9. 最终交付

- GitHub 仓库地址与可访问的网站地址（若已部署）。
- 实际表情包数量、分类、来源和许可统计。
- 完整源码、README、部署说明、数据协议、导入工具。
- 自动化测试结果和已知问题。
- ChatGPT 集成实测报告：已实现、未实现、受平台限制功能。
- 后续迭代路线与可恢复的开发进度。

**最终愿景**：让 GPT 酱拥有自己的表情包收藏室，能在技术条件允许时自然地用图片表达情绪。
